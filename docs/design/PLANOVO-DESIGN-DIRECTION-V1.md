# Planovo: design direction v1

Дата: 27 июля 2026
Статус: approved working direction for the redesign branch
Принцип: **Precision in motion — одна опубликованная версия**

## 1. Задача дизайна

Сайт должен выглядеть не как «AI/SaaS с набором карточек», а как точный
операционный продукт для живого учебного процесса. Визуальная система
объясняет причинность:

> правило → конфликт → решение человека → опубликованная версия → роли

Красота возникает из ясности связей, типографики, масштаба интерфейса и
сдержанного движения, а не из декоративного 3D.

## 2. Что сохраняем из первого черновика

- Onest для смыслового текста и IBM Plex Mono для времени, версий и статусов;
- тёмный premium-контур;
- тонкую координатную сетку;
- крупный редакционный H1;
- реальный объект расписания в hero;
- честное разделение «работает / следующий этап / roadmap»;
- один яркий функциональный акцент;
- отсутствие сфер, custom cursor, scroll hijacking и бесконечного glow.

## 3. Что меняем и почему

| Первый черновик | Изменение | Причина |
|---|---|---|
| Чёрный + acid lime как основной характер | Холодный графит + register blue; mint, coral и amber только для состояний | Black/acid стал распространённым «AI-premium» кодом и слабо связан с учебным процессом |
| Три самостоятельных product-макета | Один persistent object занятия | Одна причинная история сильнее трёх декоративных dashboard |
| UI 7–11 px | Ключевой demo UI не меньше 12–14 px mobile и 13–15 px desktop | Доказательство должно читаться директором без zoom |
| 46/30/24% роли | «Вся сетка / своя загрузка / свой день» | Проценты выглядят как выдуманная аналитика |
| Длинная цепочка повторяющих секций | Объединённые workflow + roles и implementation + coexistence | Текущий mobile почти 19 000 px и теряет конверсионный ритм |
| Product stage после первого mobile viewport | Видимый фрагмент сетки у нижней границы первого экрана | Посетитель должен увидеть продукт в первые секунды |
| Публикация магически меняет время и кабинет | Явный конфликт 312 → выбор 214 → публикация | Motion обязан объяснять причину, а не подменять данные |

## 4. Pass 1 — token system

### Color roles

Цвета задаются семантически; точные значения проверяются в браузере по
контрасту:

- `canvas`: холодный blue-black, не абсолютный чёрный;
- `surface`: слегка более светлый графит;
- `surface-raised`: панель активного product stage;
- `ink`: мягкий белый;
- `muted`: холодный серо-голубой;
- `line`: малоконтрастная координатная линия;
- `action`: register blue для CTA и управляемого выбора;
- `published`: mint только для валидного опубликованного состояния;
- `conflict`: coral только для ошибки/конфликта;
- `draft`: amber только для черновика/ожидания проверки.

Нельзя использовать один акцент одновременно для CTA, успеха, ошибки и
декора — состояние должно считываться без подписи, а подпись остаётся для
доступности.

### Typography

- Display: Onest 650–720, tight tracking, короткие строки.
- Body: Onest 400–520, line-height 1.45–1.6.
- Product labels: IBM Plex Mono 500–600, uppercase только для коротких
  меток.
- Hero max line length: 10–13 слов в визуальной группе.
- Body max measure: 58–68 characters.
- Product UI minimum: 13 px desktop, 12 px mobile; важные значения 14–16 px.

### Space and shape

- Основной шаг: 4 px; рабочие интервалы 8 / 12 / 16 / 24 / 32 / 48 / 72.
- Радиусы небольшие и функциональные: 8 / 12 / 16; без «пузырей».
- Border-first surfaces вместо тяжёлых теней.
- Touch target: минимум 44 × 44 px.
- Секции отделяются ритмом и изменением композиции, не случайным цветным
  фоном.

## 5. Pass 2 — layout and signature object

### Desktop

Hero делится примерно 45/55:

- слева: audience, H1, lead, CTA и platform bridge;
- справа: увеличенный sticky product stage;
- UI stage остаётся читаемым при 1280–1600 px;
- нижний край stage подсказывает, что сценарий интерактивен.

После hero один и тот же блок занятия продолжает историю:

1. выделяется в сетке;
2. переносится на 13:20 в аудиторию 312;
3. получает конфликт аудитории;
4. показывает свободную 214 как доступный вариант, но не «AI-рекомендацию»;
5. сотрудник выбирает 214;
6. версия публикуется;
7. появляются teacher/student representations и запись истории.

Текстовые этапы управляют состоянием stage. Пользователь всегда может выбрать
этап кнопкой; scroll не перехватывается.

### Mobile

- H1 сокращается за счёт новой формулировки.
- У нижней границы первого viewport виден заголовок или верх сетки product
  stage.
- Показывается один день и одно занятие, не уменьшенная недельная таблица.
- Три крупных состояния: «Изменение», «Конфликт и решение», «Опубликовано».
- Ролевые views идут ниже как продолжение той же карточки.
- Sticky отключается; весь сценарий читается линейно без motion.

## 6. Motion grammar

Разрешённые движения:

- `transform` и `opacity`;
- короткий spatial move одного занятия;
- border/color state transition;
- pulse от опубликованной версии к ролям;
- progress line, которая показывает фазу, а не декоративное время.

Ограничения:

- 180–320 ms для micro-state;
- 400–650 ms для перехода одного объекта между фазами;
- без постоянных циклов;
- без parallax на тексте;
- без smooth-scroll на длинные дальние якоря;
- reduced motion показывает те же данные без пространственного перемещения;
- SSR/no-JS оставляет читаемое опубликованное состояние или отдельный
  статический fallback.

## 7. Page rhythm

Целевая композиция главной:

1. Hero + рабочий сценарий + CTA.
2. Первый клиентский контур и техническое доказательство.
3. Workflow + три роли в одном persistent stage + CTA.
4. Статусная карта продукта.
5. Case: «было → создаётся → что измерим» + CTA.
6. Внедрение + coexistence + слой для директора.
7. Akeda, FAQ.
8. Final CTA.

Не больше трёх содержательных экранов между точками конверсии.

## 8. Proof hierarchy

По силе доказательства:

1. обезличенный реальный экран KEMS;
2. воспроизводимый интерактивный сценарий;
3. подтверждённый capability inventory;
4. статус первого оплаченного проекта;
5. только затем — концептуальная схема.

Стилизованный demo всегда помечается как «демонстрационный сценарий». Логотип,
название и testimonial колледжа появляются только после разрешения.

## 9. Accessibility and performance gates

- WCAG AA для текста и управляющих элементов;
- focus-visible у каждого интерактивного элемента;
- состояние не передаётся только цветом;
- target 44 × 44 px;
- keyboard и Escape для modal;
- без горизонтального overflow на 360–430 px;
- product proof читается без zoom;
- одна motion-библиотека;
- WebGL не подключается;
- `prefers-reduced-motion` покрывает CSS и JS;
- OG-изображение использует тот же знак и ту же систему цвета.

## 10. Критерий успеха

Если убрать текст, посетитель всё равно должен понять: есть расписание,
возникает конфликт, человек выбирает допустимое решение, появляется новая
версия, а её видят разные роли.
